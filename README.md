# Deep Schema

A survival-themed study game for **ITSC 3160: Database Design and Implementation** (UNC Charlotte).
You're stranded on an ocean planet with a submarine. Each depth zone is one lecture. You dive to scan targets (multiple-choice questions), open salvage crates (sorting and SQL-ordering puzzles), and fight creatures that stand for bad database practices. Creatures also raid the seabase at random, and you defend it by answering their questions.

Built with [Phaser 3](https://phaser.io/) and plain JavaScript. There is no build step needed to play.

## Play it

- **On your computer:** double-click `index.html`. It has the whole game in one file.
- **Online (GitHub Pages):** in the repository go to **Settings → Pages**, set **Source** to *Deploy from a branch*, pick `main` and `/ (root)`, and save. After a minute the game is live at `https://<your-username>.github.io/<repo-name>/`.

Progress is saved in the browser's local storage.

## Bloom levels

Every question is tagged with a level of Bloom's taxonomy:

| Level | Name | What the questions ask |
|---|---|---|
| 1 | Remember | Recall facts and terms |
| 2 | Understand | Explain why and what it means |
| 3 | Apply | Use it on a concrete example (predict output, compute a closure) |
| 4 | Analyze | Break it down and find the problem (find the error, diagnose a normal form) |
| 5 | Evaluate | Judge which design or query is best and why |
| 6 | Create | Write the SQL or design the tables yourself (fill in the blank) |

Each zone has its own ladder. Before a dive you pick any level you've unlocked. Getting 4 more questions right than wrong at your top level unlocks the next one, and the game asks whether you want to move up. Every dive also mixes in a review question from the levels below. Questions you miss are saved in the Databank (My dive log) until you get them right.

## Project layout

```
index.html            the playable game, all in one file (generated by build.py, don't edit)
dev.html              the same page, loading the source files below (for development)
styles.css            all styles
config/config.js      tuning: oxygen, rewards, raids, shop items, cosmetics
src/
  data/content.js     questions, salvage crates and creatures for each zone
  data/bloom.js       Bloom level names and the higher-level questions (Apply to Create)
  data/studyguide.js  Databank definitions and the GROUP BY / HAVING walkthrough
  systems/            game rules: dives, raids, the Bloom ladder, the economy
  ui/                 the PDA panel, HUD, tutorial, touch controls
  art/                everything drawn in code (no image files)
  scenes/             Phaser scenes: boot, seabase, dive
  entities/           the submarine and creatures
  main.js             entry point
build.py              bundles dev.html + styles.css + src/ into index.html
```

## Editing

1. Change the source files: questions in `src/data/content.js`, Databank entries in `src/data/studyguide.js`, balance numbers (oxygen, rewards, raid timing) in `config/config.js`.
   A multiple-choice question looks like `{ lv: 3, q: "...", a: "correct answer", w: ["wrong", "wrong", "wrong"], why: "explanation", code: "optional SQL shown in a code block" }`.
   A fill-in-the-blank question uses `t: "blank"` and `acc: ["accepted", "answers"]` instead of `w`.
2. To try changes before building, open `dev.html` through a local server. Browsers block the source files when a page is opened straight from disk, so double-clicking `dev.html` shows only the top bar.
   - VS Code: install the *Live Server* extension, right-click `dev.html`, then **Open with Live Server**.
   - Or in a terminal in this folder: `python -m http.server 8000`, then open <http://localhost:8000/dev.html>.
3. Run `python build.py` to rebuild `index.html`, then commit both.
